# 从 MP3 制作科普动画

这是供具备文件读写、程序执行和媒体查看能力的 AI 编程助手使用的制作流程，基于 PDoomVideo。AI 助手编写分镜和动画；随 Skill 提供的工具负责转录、数据校验、渲染及合成。最终交付 MP4、独立 SRT、分镜和可编辑场景代码。画面需要实际表达旁白中的概念、因果和过程，不能仅靠替换图片完成制作。

## 开始使用

将整个 `science-video/` 文件夹导入所用 AI 编程助手的 Skill 目录，或让助手直接读取其中的 `SKILL.md`。分享时保留 `references/` 和 `assets/runtime/`，它们分别提供制作与绘画说明、实际运行工具。

用户提供已录好的 MP3 附件或可访问的文件路径，即可发出制作请求：

> 使用 science-video，将我提供的 MP3 旁白制作成科普动画。保留水彩手绘风格，1920×1080、24 fps，交付成片、独立字幕、分镜和可编辑源码。

用户可同时提供 SRT、原稿、视频标题、画幅、参考风格或审批阶段。已有旁白直接使用，不重新写旁白或生成配音。

## 输入与环境

1. 先读取 [制作与运行说明](references/SCIENCE_VIDEO.md)，检查当前环境中的 Node.js、p5.js、p5.brush、Puppeteer、Chrome 或 Edge、FFmpeg 与 FFprobe。优先复用当前工作区内兼容的 PDoomVideo 科普视频工具；没有时，将随包提供的 [运行工具](assets/runtime/) 复制到用户工作区的独立目录，依据依赖清单配置环境。运行工具的位置以实际复制位置为准，不依赖分享者的仓库路径。
2. 由助手根据当前操作系统、Shell、实际工具位置和工具支持的参数执行环境检查、初始化、转录、构建、预览、渲染与合成。缺少 Node 依赖时，按随包的依赖清单与锁定文件安装。Chrome、FFmpeg、FFprobe、Python 和任务目录均可指定实际位置，不能假定接收者使用某个磁盘或预设路径。
3. 仅有 MP3 时使用本地 faster-whisper。缺少转录环境时，在工作区的运行工具目录创建隔离的 Python 环境，并按提供的转录依赖清单安装；解释器位置根据当前操作系统发现。默认中文、small 模型、CPU / int8，保留词时间戳。首用模型下载到 Hugging Face 缓存或用户指定的模型目录；模型已缓存后可离线转录。不需要 OpenAI API Key。
4. 若用户同时提供 SRT，直接导入，不必安装或调用语音识别。没有实际 MP3 附件或可访问路径时，说明所缺输入，不用内置歌曲代替；没有用户提供的旁白或其明确指定的语音输入时，不声称完成正式视频。
5. 首次使用可能需要下载依赖和转录模型。环境缺少必要工具且无法配置时，明确说明缺少的项目和已完成的阶段；不能把 Skill 文本当作已经安装好的运行环境。

初始化时默认 1920×1080、24 fps、水彩手绘风格。用户要求竖屏时采用 1080×1920，其他画幅、帧率、风格按用户要求配置。每条视频使用独立任务目录，分镜、字幕、场景、预览和成片分开保存；原 MP3 只复制，实际音频长度是整条时间线的依据。

## 旁白、分镜与场景

1. 读取生成的 `transcript.json` 和 `transcript.txt`。核对中文、科学术语、数字、单位和英文缩写；转录文字不确定时参考用户原稿或核对对应音频，不擅自编造内容。保留真实时间戳，不按字数估计整段 MP3 的时序。需要科学事实核验时查一手来源，在分镜记录来源及不确定性，不改写已录旁白。
2. 将旁白拆成连续的场景，覆盖 `0` 到 `project.json.duration`，不留空白或重叠。在任务自己的 `STORYBOARD.md` 写清起止时间、旁白、讲解目标、主体动作、镜头、转场与模块。用可见的因果变化、比较和过程解释概念；类比与示意图需让观众能分辨，图表数值应来自旁白或实际来源。
3. 编辑任务自己的 `project.json.scenes` 和 `scenes/*.js`。详细数据格式和场景例子见 [制作与运行说明](references/SCIENCE_VIDEO.md)；绘画、角色与材质 API 见 [绘画参考](references/ANIMATION_GUIDE.md)。使用其绘画机制，不沿用原歌曲的内容、固定时长、章节、字幕区、P(doom) 仪表或固定节拍；按实际旁白中的概念和因果安排运动。每个场景以 IIFE 隔离私有函数，调用 `chapter(scene.id, start, end, [[shotStart, draw], ...])`；场景 id、起止时间与配置一致，每个镜头起点使用全片时间。
4. 场景函数接收 `draw(t, lt, dur)`，分别表示全片时间、当前镜头经过时间和镜头时长，每帧完整绘图。使用 `W`、`H` 布局，运动从时间计算；用 `hash` 做稳定随机，不依赖上一帧，不用 `Math.random()`，支持并行、乱序渲染。`camBegin` 与 `camEnd` 配对。核心文字使用当前环境可用的中文字体，字幕留出底部约 18% 的空间。原 Clawd 角色是可选素材，不强制出现在科普视频里。
5. 在 `transcript.json` 校正字幕或拆分过长字幕。自动转录保留词时间戳，可用于精细拆分；不默认做逐字卡拉 OK。`transcript.json` 是字幕权威来源，修改后用构建工具同步更新独立 SRT、文本和预览页面，不能只修改生成文件。实际场景实现完成后，将对应场景状态设为 `ready`；不能仅修改状态，把占位画面当作完成品。

## 预览、渲染和交付

依次执行关键帧联系表、带原音频的短片段预览、项目完整性检查和最终全片渲染。时间点与片段范围按实际旁白和场景选择，不能套用其他视频的固定参数；短片段范围不能超出音频时长。

- 用当前环境的图片查看工具检查联系表中的中文、构图、信息层级、字幕遮挡及关键转场。抽查每个场景、镜头的起止和主体动作中间时刻；片尾取最后有效帧。连续运动、音画同步与声音需检查编码后的片段，不能仅凭几张帧证明。
- 迭代有问题的场景后再渲染。缓存按输入与代码内容分目录，原样重跑会续渲；修改动画后不会复用旧画面。先用 1–2 个 worker，依据 GPU 与实测速度调整。
- 最终渲染默认完成全片逐帧绘制、FFmpeg 合成和媒体校验。中断后用相同任务配置继续；只有当前版本的帧已全部绘完时，才能单独合成。草稿选项只用于预览，不能绕过最终制作检查；最终渲染要求所有场景实际完成且状态为 `ready`。
- 检查最终视频的分辨率、帧率、时长、视频与音频流、编码及独立字幕。媒体结构检查通过，不代表科学事实、视觉质量、声音语义或音画同步已通过；这些内容需按实际查看或试听情况分别说明。
- 交付任务目录中的 `out/video.mp4`、`subtitles.srt`、`STORYBOARD.md`、`scenes/` 和 `out/verification.json`，提供用户可打开的实际文件位置或下载入口。在可访问本地文件的环境中使用交付物的绝对路径。保留原 MP3 副本、项目配置、字幕源和可编辑源码，说明实际检查覆盖、尚未核实的内容或失败。

用户明确要求先审分镜或先选风格时，在该阶段提供具体成果并等待选择。否则按已授权范围连续完成制作，不额外增加审批步骤。默认由当前助手连续完成，不因原项目文档中的分工示例自动委派。
